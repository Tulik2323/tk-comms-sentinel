# מדריך שימוש — TK Comms Sentinel

## מה המערכת עושה

TK Comms Sentinel מנטרת את מתגי הרשת (סוויצ'ים) ומתריעה כשמשהו לא תקין: מתג שנפל, פורט עמוס, CPU או זיכרון גבוהים, או נפילה של כל הרשת יחד. היא גם שומרת היסטוריה, כדי שאפשר יהיה לבדוק מה קרה ומתי.

- **בדיקה מלאה (SNMP) כל 5 דקות** לכל מתג: פורטים, תעבורה, CPU, זיכרון, טמפרטורה, ספקי כוח, ותחנות הקצה שמחוברות לכל פורט.
- **בדיקת זמינות מהירה (ping) כל 20 שניות.** מכשיר שלא עונה בשתי בדיקות ברצף (כ-40 שניות) נבדק גם ב-SNMP. רק אם גם SNMP לא עונה, הוא מסומן כנופל ונשלחת התראה.
- **התראות** נשלחות במייל ובטלגרם, לפי מה שמנהל המערכת בחר. גם **אתחול של מתג** (זמן הפעולה שלו התאפס) נשלח, באותו ערוץ של התראות הנפילה.
- **המערכת שומרת על עצמה**: אם תהליך הניטור מפסיק לעבוד, או שהדיסק של השרת מתמלא, נשלחת התראה בטלגרם ובמייל (בלי קשר לסוגי ההתראות שנבחרו), ובראש כל מסך מופיע פס אדום.
- המערכת **רק קוראת** מהמתגים. היא לא משנה בהם שום הגדרה.

יש שני תפקידים:

| תפקיד | מה אפשר |
|---|---|
| צופה (Viewer) | לראות את כל מסכי הניטור, ההתראות והמלאי |
| מנהל (Admin) | כל מה שהצופה רואה, ובנוסף: הוספה ומחיקה של מכשירים, ספי התראה, סגירת התראות, הגדרות, משתמשים, Audit, אבחון, דוחות ורישוי |

## איך נכנסים

1. פותחים בדפדפן את כתובת המערכת שקיבלתם ממנהל המערכת.
2. מקלידים שם משתמש וסיסמה: חשבון הדומיין (AD) או חשבון מקומי שמנהל המערכת יצר.
3. בכניסה הראשונה מוצג **קוד QR**. סורקים אותו באפליקציית אימות (Google Authenticator או Microsoft Authenticator) ומקלידים את הקוד בן 6 הספרות.
4. בכל כניסה אחר כך מקלידים את הקוד מהאפליקציה.

משך ההתחברות נקבע לכל משתמש על ידי מנהל המערכת (ברירת המחדל: 8 שעות). כשהוא נגמר, המערכת מבקשת להיכנס שוב. ליציאה לוחצים **יציאה** בתחתית התפריט.

## המסכים בתפריט

התפריט נמצא בצד המסך. ליד הלוגו מופיע מספר הגרסה. מתחת לו תיבת חיפוש, ובתחתיתו מעבר לאנגלית (EN), מצב כהה או בהיר, ושם המשתמש.

כשמופיע **פס אדום** בראש המסך ("הניטור לא פועל מאז..."), הנתונים במסך ישנים ולא נשלחות התראות. ראו בעיות נפוצות למטה.

| מסך | מה עושים בו |
|---|---|
| חיפוש (בראש התפריט) | מוצאים מתג לפי שם או IP, או מחשב ומדפסת לפי IP או MAC, ורואים לאיזה מתג ופורט הם מחוברים |
| לוח בקרה | תמונת מצב של כל הרשת: כמה מכשירים פעילים, התראות פתוחות, הפורטים העמוסים והמתגים החמים. **היסטוריית נפילות** מראה נפילות, אתחולים של מתגים (כמה מתגים שאותחלו יחד מופיעים בשורה אחת) ותקופות שבהן הניטור לא פעל. מתרענן כל 30 שניות |
| מכשירים | רשימת המתגים. נקודה ירוקה = פעיל, אדומה = לא זמין. לחיצה על שם פותחת את דף המתג: גרפים, מצב חומרה, טבלת פורטים ותמונת המתג (Switch Layout) |
| טופולוגיה | ציור של החיבורים בין המתגים. צבע הקו מראה את העומס |
| מפה | המתגים על תוכנית הבניין |
| התראות | כל ההתראות, פתוחות וסגורות. בראש המסך: התראות שחוזרות שוב ושוב ודורשות בדיקה. מנהל מגדיר כאן גם ספי התראה |
| שינויי פורטים | יומן של 14 יום: חיבור וניתוק של כבל, שינוי VLAN, מהירות, תיאור והשבתת פורט |
| Watchdog | מעקב חי אחרי פורטים של מתג נבחר, כל 3 שניות, עם צליל. מתאים לעבודה בארון תקשורת |
| ניתוח מגמות | שינויי פורטים לפי יום, פורטים שעולים ויורדים שוב ושוב, ופורטים עם שגיאות |
| מלאי | כל הציוד שמחובר לפורטים, מסווג לפי סוג (מחשבים, מדפסות, מצלמות ועוד), ושמות ה-VLANים |
| Audit (מנהל) | יומן של כל הפעולות במערכת: כניסות, שינויים, מכשירים שנפלו וחזרו |
| אבחון (מנהל) | בדיקות ping, פורטים ו-SNMP מהשרת של המערכת אל מכשיר |
| דוחות (מנהל) | הפקת דוחות והגדרת דוחות שנשלחים במייל אוטומטית |
| ניהול (מנהל) | הגדרות מערכת (מייל, טלגרם, AD, שעות שקט, עדכונים) ומשתמשים |
| רישוי (מנהל) | הפעלת רישיון המערכת |
| עזרה | המדריך הזה |

## פעולות נפוצות

### לאיזה פורט מחובר מחשב?

1. מקלידים בתיבת החיפוש את כתובת ה-IP או ה-MAC של המחשב.
2. בתוצאה רואים את המתג ואת הפורט.
3. לוחצים על התוצאה: נפתח דף המתג, והפורט מודגש.

### בדיקת מתג שנפל

1. ב**לוח בקרה** מופיע פס אדום עם שם המתג.
2. ב**מכשירים**, ליד המתג, לוחצים **בדיקה** כדי לבדוק אותו מיד.
3. מנהל יכול לבדוק ב**אבחון** אם המתג עונה ל-ping ול-SNMP מהשרת.

### מעקב אחרי פורטים בזמן עבודה בארון

1. פותחים **Watchdog**.
2. מסמנים את המתג (אפשר לחפש לפי שם) ולוחצים **התחל ניטור**.
3. מחברים או מנתקים כבל: הפורט שהשתנה מופיע מיד, עם צליל.
4. בסיום לוחצים **עצור**.

### הוספת מתג לניטור (מנהל)

1. ב**מכשירים** לוחצים **+ הוסף**.
2. ממלאים כתובת IP, שם, גרסת SNMP ופרטי הגישה, ומיקום.
3. לוחצים **הוסף מכשיר**. המערכת בודקת אותו מיד.

אפשר גם **סרוק** (חיפוש בטווח כתובות) או **ייבוא CSV** (רשימה מקובץ).

### הגדרת סף התראה (מנהל)

1. ב**התראות** פותחים את לשונית **הגדרות סף** ולוחצים **+ הוסף סף**.
2. בוחרים מכשיר (או את כל המכשירים) ומטריקה: תעבורה, CPU או זיכרון.
3. קובעים את הסף באחוזים, וכמה דקות הערך צריך להישאר מעליו לפני שנשלחת התראה.
4. לוחצים **שמור**.

לפורט בודד קובעים סף מחלון הפורט, בדף המתג.

### חיבור התראות לטלגרם (מנהל)

1. בטלגרם פותחים צ'אט עם **BotFather**, שולחים `/newbot` ומקבלים Token.
2. ב**ניהול** ← **הגדרות** מדביקים אותו ב-**Bot Token**.
3. שולחים לבוט הודעה, לוחצים **מצא Chat ID** ובוחרים את הצ'אט.
4. מסמנים **שלח התראות לטלגרם** ובוחרים אילו התראות יישלחו.
5. לוחצים **שלח הודעת בדיקה**, ואחר כך **שמור הגדרות**.

## בעיות נפוצות ומה לעשות

| מה רואים | מה עושים |
|---|---|
| פס אדום: "הניטור לא פועל מאז..." | תהליך הניטור לא פועל. למנהל השרת: לבדוק שיש מקום פנוי בדיסק, ושהמשימה המתוזמנת **NetMonitor Poller** רצה. כשהניטור חוזר נשלחת הודעה, והפס נעלם תוך דקה |
| פס כתום: מקום פנוי נמוך בדיסק | לפנות מקום בדיסק של השרת. כשהדיסק מתמלא, הניטור נעצר |
| ליד מתג כתוב "⚠️ לא נבדק מאז..." | המתג לא נקרא ב-SNMP מאז השעה הזו, והנתונים שלו (כולל זמן הפעולה) ישנים. ב**אבחון** בודקים ping ו-SNMP אליו |
| לא הגיעה התראה | בודקים ב**התראות** אם היא נרשמה. אם כן, בודקים ב**ניהול** שסוג ההתראה מסומן למייל או לטלגרם, שהמתג "שלח התראות לטלגרם" מסומן, ושלא עכשיו שעות שקט. שולחים מייל בדיקה או הודעת בדיקה |
| מתג מסומן כנופל, אבל הוא עובד | ב**אבחון** בודקים ping ו-SNMP. סיבות נפוצות: פרטי גישה (Community) שגויים, או רשימת גישה במתג שחוסמת את השרת |
| נתון חדש לא מופיע | רוב הנתונים מתעדכנים בבדיקה הבאה, תוך 5 דקות |
| כבל נותק ולא נרשם בשינויי פורטים | חיבור וניתוק נבדקים כל 5 דקות. ניתוק קצר יותר עלול לא להירשם. למעקב מדויק משתמשים ב-Watchdog |
| אותו פורט מתריע כל יום | אם העומס תקין עבורו, קובעים לו סף משלו מחלון הפורט |
| הוחלף טלפון, אין קוד כניסה | מנהל לוחץ **איפוס 2FA** ליד המשתמש ב**ניהול**. בכניסה הבאה סורקים קוד חדש |
| הודעה שהרישיון או תקופת הניסיון הסתיימו | מנהל פותח **רישוי**, שולח לספק את טביעת האצבע של המחשב ומדביק את המפתח שקיבל |

## כללי זהירות

- **שינוי הגדרות נשמר רק אחרי "שמור הגדרות"**, בתחתית מסך הניהול. כל עוד מופיעה ההודעה "יש שינויים שלא נשמרו", השינוי לא נכנס לתוקף.
- **מחיקת מכשיר מוחקת גם את כל ההיסטוריה שלו**: גרפים, פורטים, נפילות וספי התראה. אי אפשר לבטל.
- **"נקה ישן" ב-Audit מוחק רשומות לצמיתות.**
- **לא מעבירים לאחרים את קוד ה-QR או את הקוד מאפליקציית האימות.**
- **במחשב משותף יוצאים מהמערכת** בסוף העבודה.
- **התקנת עדכון מפעילה מחדש את המערכת** לכדקה. עדיף לעדכן בשעה שקטה.
